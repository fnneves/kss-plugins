# scaffold-project

Initializes the `.kss/` planning shell at the project root. Creates the project-level files and the empty topics/spikes/codebase folders. Run once per project, before any other skill.

## Pre-flight

1. **Refuse if `.kss/` already exists.**
   - Tell the user: "`.kss/` already exists at `<absolute-path>`. Refusing to overwrite. If you want to start over, archive or remove the existing `.kss/` first."
   - Exit.

2. **Optional: spec file.**
   - Ask: "Do you have a markdown file with project details? Provide an absolute path, or press Enter to describe interactively."
   - If a path is given, read it.

## Process

1. **Gather inputs.**
   - **Project name** (e.g. `predictions-repo`). Use the directory name as a default suggestion.
   - **One-line description** (what is this thing).
   - **Optional**: tech stack hint, existing constraints. (Skip if not offered.)

2. **Create the directory tree.**

   ```bash
   mkdir -p .kss/codebase .kss/topics .kss/spikes
   ```

3. **Write the two root files** using the templates below: `PROJECT.md`, `CANONICAL-KB.md`.

4. **Offer to map the codebase now (SUGGEST-AND-CONFIRM).**
   - "Scaffold complete. Run `map-codebase` now to generate the codebase snapshot? [y/N]"
   - On yes: hand into `map-codebase`. On no (default): remind — "Run `map-codebase` when ready, then `new-topic` to start your first topic."

5. **Do not commit.** Let the user decide.

## Template: `.kss/PROJECT.md`

```markdown
---
name: {project-name}
created: {YYYY-MM-DD}
active_topic: null
last_session: null
last_updated: {YYYY-MM-DD}
---

# {project-name}

## What This Is

{user-provided one-line description}

## Topics

(none yet — run `new-topic` to start one)

## Archived Topics

(none)

## Carryover (cross-topic handoffs)

(none — lazy-populated by `complete-milestone` when work is deferred to a future topic)

## Tech Stack

(refresh via `map-codebase`)

---
*Generated by scaffold-project on {YYYY-MM-DD}*
```

`active_topic` is the single project-level pointer — a topic slug, or `null` when no topic is active. `last_session` is bumped by session skills. The active milestone lives in the active topic's `.kss/topics/{active_topic}/STATE.md` frontmatter — its single source of truth.

## Template: `.kss/CANONICAL-KB.md`

```markdown
---
name: {project-name}-canonical-kb
created: {YYYY-MM-DD}
last_updated: {YYYY-MM-DD}
---

# Canonical Knowledge Base

Cross-topic insights distilled from session work. Update via `distill`.

Organize entries into the three sections below. Add entries newest-on-top within each section.

## Insights

(empty)

## Patterns

(empty)

## Gotchas

(empty)

---
*Generated by scaffold-project on {YYYY-MM-DD}*
```

## Output

After running, the user has:

```
.kss/
├── PROJECT.md        (frontmatter holds active_topic — the single project pointer)
├── CANONICAL-KB.md
├── codebase/   (empty)
├── topics/     (empty)
└── spikes/     (empty)
```
